# Forge 设计说明:实现思路 · 完成度 · 扩展路线

> 面向后续维护者。架构与部署速查见 README,本文记录「为什么这么做」「做到哪了」「接下来怎么走」。
> 更新于 2026-10-08,对应生产版本 a1b29471 之后的分段生成架构。

## 一、系统是什么

用户输入一句想法 → AI 规划出计划项目录 → 分段生成一个自包含单 HTML 网站 → 在线预览、对话迭代、发布到 `/s/:slug` 并收集访客数据。

技术底座:Cloudflare Workers(免费版)+ Workflows + D1 + Assets,前端 React + Vite + Tailwind,LLM 走 OpenAI 兼容接口(当前 glm-5.3-flash,思维链模型)。

## 二、实现思路与关键取舍

### 1. 单 HTML 产物
全部生成物是一个自包含 HTML(样式/脚本内联),存 D1 一个 TEXT 列。换取:发布零子域名/零构建、版本回滚是一行记录、访客页零外部依赖。代价:无法表达多文件工程——这是产品边界,不是缺陷(见扩展路线)。

### 2. 生成 = 确定性流水线,不是 agent
`claim → 规划 → 骨架(占位符)→ 逐计划项 → 组装提交`,模型只做每步的「写作」,流程由代码定死。没有用任何 LLM 框架:瓶颈在毫秒级 CPU 与网关怪癖,需要对每次 fetch 的超时/重试/思维链直接控制;断点续跑这类编排需求由 Workflows 平台原生承担。

### 3. 为什么要分段(三条实测的墙)
- **waitUntil 2~4 分钟被回收**:免费版后台执行体撑不住 3~6 分钟的整页生成(实测多次)
- **10ms CPU**:token 级流式消费/转发必死(约 3.6K 行上游数据即超限,原版与重构版各验证一次)
- **网关长单请求不稳**:非流式 200~400s 即可能出现 5xx/断流(实测 214s/383s 两次)

拆成骨架 + 3~5 个计划项后,每段 1~2 分钟,全部绕开。**逐字流式因此被结构性放弃**,直到升级付费版。

### 4. 为什么顺序生成不并行
同一 API key 的并发请求被网关排队:实测 4 个并行章节耗时 43s→1min→2min→17 分钟(第 4 个被饿死)。串行 + 每项独立 checkpoint 反而更快更稳,还能把进度精确到「第几项」。

### 5. 双层恢复体系
- **实例内**:每个 step 结果被引擎 checkpoint,实例中断从最后完成的 step 恢复,LLM 步骤失败自动退避重试
- **跨任务**:每完成一个计划项,产物(骨架 + 各项 HTML)写入 `jobs.sections_json`;任务最终失败后,同项目同想法再次生成时自动继承规划与已完成项,只补缺失部分(进度显示「复用上次结果」)

### 6. 失败哲学
快速、可读、不白花钱:
- 超时分四层各司其职(段 600s / 规划 150s / 修改 600s / step 重试 20s+40s 退避),错误信息带阶段与原因
- 单个计划项重试耗尽 → 调色板风格占位块顶上,**页面照常交付**,卡片标 ✗,对话一句话补全——把「全损」变「局部可修」
- 只有成功才扣积分;失败任务的产物保留供续跑

### 7. 安全模型
发布页 `CSP: sandbox` 跑在 opaque origin,读不到主站凭证;站点数据走占位符替换的专用接口,draft/live 双环境隔离;生成的代码被提示词禁止收集敏感数据。

## 三、当前完成程度

### 已完成(生产可用)
- 注册/登录/积分(成功扣 1 分)、项目与版本、发布、站点数据双环境
- 后台生成全链路:规划卡片实时勾选(✓/●/○/✗)、骨架完成预览即现、计划项逐个生长(html_preview)、进度精确到项名
- 恢复三层:step 重试/checkpoint、cron 巡检(errored 实例判死解锁)、跨任务断点复用
- 优雅降级 + 对话补全引导
- 可观测性:`[llm]`/`[job]`/`[wf]` 日志(wrangler tail)、错误自诊断(阶段前缀、超时与网关错误区分、网关原始信息透传)

### 未做 / 受平台或设计约束
| 项 | 原因 |
|----|------|
| 逐字流式输出 | 免费版 10ms CPU 硬限制,需付费版(30s CPU 起步) |
| chat 修改无中间进度 | 整页重写是单次调用,任意 HTML 无法安全切分 |
| 图片素材 | 提示词禁外部图片,仅渐变/SVG/emoji;未接图片生成或图库 |
| 多页面/多文件站点 | 单 HTML 产物设计边界 |
| 版本回滚 UI | versions 数据已存,缺界面 |

## 四、扩展路线与优先级

判断标准:用户痛感 × 实现成本 × 平台约束。

### P0 — 直接解决已知痛点
1. **非思考模型通道**:glm 思维链是速度瓶颈的大头(每段都付思考前缀)。加一个备用模型配置(如 deepseek-chat),先用脚本实测稳定性再切换。成本:两个 secret + 半小时验证
2. **按计划项修改**:把「补全失败板块」泛化为「对话指定改哪一项」——只重写被点名的计划项并回填,复用现有分段机制。修改从分钟级整页重写变为秒级局部更新。成本:1~2 小时
3. **版本历史 UI**:时间线 + 一键回滚,数据层已就绪。成本:小时级

### P1 — 产品完整性
4. **真流式输出**:升级 Workers 付费($5/月,CPU 30s+),`streamChat` 消费 + 节流转发,逐字上屏(代码基础都在)
5. **规划可编辑**:生成前允许用户增删/改写计划项再继续,人对齐质量的把控点
6. **图片能力**:接图片生成 API 或免费图库,R2 存储资源,解除「无图网站」的最大观感限制

### P2 — 规模化与演化
7. **多页面 + 独立资源**:引入 R2/文件表作为「文件系统」,给模型 read/write 工具,从固定流水线演化成真 agent 循环(自检评审 step + 选择性重写是第一步)
8. **配额与治理**:免费版实例并发限制、注册审核、积分付费、滥用防护
9. **多模型路由**:规划用强模型、正文用快模型、评审用便宜模型,按 step 配置

## 附:运维速查

```bash
npx wrangler tail                                  # 实时日志([llm]/[job]/[wf] 前缀)
npx wrangler workflows instances describe \
  forge-generation <jobId>                         # 查某次生成跑到哪个 step、各步耗时
npx wrangler d1 execute DB --remote --command "…"  # 查任务表(jobs.status/error/progress)
npm run deploy                                     # 发布(自动含 workflow 与 cron)
```

超时/重试等参数集中在 `src/workflow.ts` 顶部常量与 `src/lib/llm.ts`,改完 `npm run deploy` 即生效。
